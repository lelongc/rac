# Chương 5: Dịch Vụ Web (Web Services)

## 1. Tổng Quan & Cơ Sở Hạ Tầng Web Services

Web Service là các phần mềm được thiết kế để hỗ trợ tương tác giữa các máy tính với nhau qua mạng thông qua các giao diện chuẩn.

### Các thành phần hạ tầng (Web Services Infrastructure):
1. **URI / URL / URN**: Định danh tài nguyên dịch vụ.
2. **XML (Extensible Markup Language)**: Định dạng dữ liệu tự mô tả dùng để đóng gói thông điệp.
3. **HTTP / SMTP / Giao thức vận chuyển**: Giao thức truyền tải thông điệp XML qua mạng.
4. **SOAP (Simple Object Access Protocol)**: Định dạng đóng gói thông điệp yêu cầu/phản hồi.
5. **WSDL (Web Services Description Language)**: Ngôn ngữ XML mô tả giao diện và khả năng của Web Service.
6. **UDDI (Universal Description, Discovery, and Integration)**: Dịch vụ thư mục để đăng ký và tìm kiếm Web Service.
7. **Choreography & Security**: Bảo mật và kịch bản phối hợp nhiều dịch vụ.

---

## 2. Mô Hình Tổng Hợp Dịch Vụ (Service Composition)

Các Web Service độc lập có thể được kết hợp để tạo thành một dịch vụ phức hợp cấp cao hơn.
* *Ví dụ*: Dịch vụ **Travel Agent Service** nhận yêu cầu từ Client và tự động kết hợp các dịch vụ khác:
  - `flight booking a`, `flight booking b` (Đặt vé máy bay)
  - `hotel booking a`, `hotel booking b` (Đặt phòng khách sạn)
  - `hire car booking a`, `hire car booking b` (Thuê xe tự lái)

## 3. Giao Thức SOAP (Simple Object Access Protocol)

SOAP định nghĩa cấu trúc thông điệp bằng XML được bọc trong một **Envelope (Bao thư)**:

### Cấu trúc thông điệp SOAP (SOAP Envelope):
* **`env:envelope`**: Phần tử gốc của thông điệp SOAP.
  - **`env:header`** *(tùy chọn)*: Chứa các phần tử tiêu đề như xác thực, giao dịch, định tuyến.
  - **`env:body`** *(bắt buộc)*: Chứa dữ liệu nội dung yêu cầu hoặc kết quả trả về (`m:exchange`, `m:arg1`, `m:arg2`).

### Ràng buộc HTTP POST trong SOAP Client-Server
Giao thức SOAP thường được truyền đi qua HTTP POST Request:
```http
POST /examples/stringer HTTP/1.1
Host: www.cdk4.net
Content-Type: application/soap+xml
Action: http://www.cdk4.net/examples/stringer#exchange

<env:envelope xmlns:env="http://www.w3.org/2003/05/soap-envelope">
    <env:header> </env:header>
    <env:body>
        <m:exchange xmlns:m="http://www.cdk4.net/examples/stringer">
            <m:arg1>Hello</m:arg1>
            <m:arg2>World</m:arg2>
        </m:exchange>
    </env:body>
</env:envelope>
```

## 4. Ngôn Ngữ Mô Tả Dịch Vụ Web (WSDL - Web Services Description Language)

WSDL là một tài liệu XML mô tả đầy đủ cách thức giao tiếp với một Web Service.

### 5 Thành phần cốt lõi trong WSDL (`definitions`):
1. **`types`**: Định nghĩa các kiểu dữ liệu sử dụng (thường dùng XML Schema - XSD).
2. **`message`**: Định nghĩa các thông điệp dữ liệu vào/ra (`ShapeList_newShape`, `ShapeList_newShapeResponse`).
3. **`interface` / `portType`**: Định nghĩa nhóm các thao tác (Operations) mà dịch vụ hỗ trợ.
4. **`bindings`**: Quy định cách ánh xạ các giao diện/thao tác vào giao thức cụ thể (ví dụ: SOAP over HTTP, RPC/Document style).
5. **`services`**: Chỉ định địa chỉ URL cụ thể (Endpoint Location) của dịch vụ (`http://localhost:8080/ShapeList...`).

### Các mô hình trao đổi thông điệp WSDL (Message Exchange Patterns):
* **In-Out**: Client gửi Request, Server trả về Reply (có thể trả về Fault).
* **In-Only**: Client gửi Request, Server không trả lời kết quả cũng như không báo lỗi.
* **Robust In-Only**: Client gửi Request, Server không trả về kết quả nhưng được phép gửi Fault nếu có lỗi.
* **Out-In**: Server gửi Request trước, Client trả về Reply.
* **Out-Only**: Server gửi Request cho Client.
* **Robust Out-Only**: Server gửi Request cho Client, Client chỉ phản hồi nếu có lỗi.

## 5. Dịch Vụ Thư Mục UDDI (Universal Description, Discovery & Integration)

UDDI là kho lưu trữ thông tin về các Web Service cho phép các doanh nghiệp công bố và tìm kiếm dịch vụ.

### Cấu trúc dữ liệu chính trong UDDI:
* **`businessEntity`**: Thông tin về nhà xuất bản (tên công ty, mô tả).
* **`businessServices`**: Danh sách họ các dịch vụ do doanh nghiệp cung cấp.
* **`bindingTemplate`**: Thông tin kỹ thuật để kết nối và gọi giao diện dịch vụ (chứa URL).
* **`tModel`**: Bản thiết kế chỉ số tham chiếu kỹ thuật và mô tả chuẩn của giao diện dịch vụ.

## 6. An Ninh Trong Web Services (Web Services Security)

Vì Web Services truyền nhận dữ liệu văn bản XML qua HTTP công khai, việc bảo mật bắt buộc phải dùng các chuẩn mã hóa XML:

### Các thuật toán dùng cho Chữ ký số XML (XML Signature)
* **Message digest**: SHA-1
* **Encoding**: base64
* **Asymmetric Signature**: DSA with SHA-1, RSA with SHA-1
* **Symmetric MAC Signature**: HMAC-SHA-1
* **Canonicalization**: Canonical XML (đưa XML về dạng chuẩn trước khi ký)

### Các thuật toán dùng cho Mã hóa XML (XML Encryption)
* **Block cipher**: TRIPLE-DES, AES-128, AES-192, AES-256
* **Key transport**: RSA-v1.5, RSA-OAEP
* **Key agreement**: Diffie-Hellman

## 7. Các Dịch Vụ Đám Mây Tiêu Biểu (Amazon Web Services - AWS)

| Dịch vụ AWS | Mô tả chức năng |
| :--- | :--- |
| **Amazon EC2 (Elastic Compute Cloud)** | Dịch vụ cung cấp máy chủ ảo có thể tùy chỉnh cấu hình tính toán và lưu trữ. |
| **Amazon S3 (Simple Storage Service)** | Dịch vụ lưu trữ đối tượng/dữ liệu phi cấu trúc dung lượng lớn trên Web. |
| **Amazon SimpleDB** | Dịch vụ CSDL lưu trữ và truy vấn dữ liệu có cấu trúc nhẹ. |
| **Amazon SQS (Simple Queue Service)** | Dịch vụ hàng đợi thông điệp đám mây hỗ trợ mô hình Message Queue. |
| **Amazon Elastic MapReduce** | Dịch vụ tính toán phân tán xử lý dữ liệu lớn bằng mô hình MapReduce. |
| **Amazon FPS (Flexible Payments Service)**| Dịch vụ hỗ trợ thanh toán điện tử trực tuyến. |
